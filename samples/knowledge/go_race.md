# Go 数据竞争排查

适用范围：Go 程序使用 race detector 得到 WARNING: DATA RACE，或怀疑多个 goroutine 并发访问共享状态。本文为 EvidenceOps 原创练习摘要。数据竞争、逻辑竞争和死锁不同；不能因为 Go 服务报错就认定是并发问题。

Go 数据竞争发生于并发访问同一内存位置、至少一个访问是写且缺少必要同步的情况。优先保留 race 报告中的冲突读写栈、goroutine 创建栈、触发用例、Go 版本与运行参数，定位两侧访问对应的共享对象。

Go 可在适合的开发或测试环境执行 go test -race ./...，并用接近实际的负载覆盖相关路径。race detector 只检测本次运行中实际发生的竞争；没有报告不能证明所有路径都没有竞争。检测会增加运行开销，平台支持和构建条件需核对。

修复 Go 数据竞争时，应明确共享状态的所有权及同步关系，按实际访问模式使用 Mutex、channel、不可变快照或合适的 atomic 操作。不能只在其中一条写路径加锁而遗漏读路径，也不能把 sleep 当作同步保证；修改后需要并发回归。

缺少 Go 竞争报告和复现路径时，应请求相关栈与共享变量访问代码，不应声称已确定具体变量或锁。参考 Go 官方 race detector 文档 https://go.dev/doc/articles/race_detector 。本文不提供自动执行用户代码或修改生产并发逻辑的工具。
